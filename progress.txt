## Iteration 1 — AUDIT-1: Backend Services Audit
**Task:** Map all 37 service files and 198+ functions to their contract review workflows.
**Files Changed:** AUDIT_MAP.md (created), REFACTOR_PRD.md (checked off)
**What I learned:**
- 37 service files with 198+ public functions organized across 25 workflow categories
- Core pipeline: gemini_analyzer.py -> analysis_pipeline.py -> rule_engine.py + rules_library.py -> hallucination_guard.py -> confidence_scorer.py -> redline_implementer.py
- AI providers: vertex_client.py (Vertex AI) -> gemini_analyzer.py (consumer Gemini) -> ai_service.py (Azure OpenAI fallback)
- Key auxiliary services: scope_analyzer, jurisdiction_detector, defined_terms_resolver, dependency_resolver
- analysis_pipeline.py is the orchestrator -- it calls gemini_analyzer, hallucination_guard, confidence_scorer, scope_analyzer, jurisdiction_detector
- intelligence_bridge.py provides Strategy pattern (OmniContext for small docs, HybridSentinel for large) but may not be actively used since gemini_analyzer.py handles the main flow now
- rules_library.py has 75 built-in rules for clause detection -- this is the default playbook
- playbook_conditions_engine.py handles conditional rule overrides based on deal context
- text_normalizer.py is critical for Word text matching (smart quotes, soft hyphens, zero-width chars)
- redline_implementer.py generates surgical word-level OOXML Track Changes using SequenceMatcher

**Patterns for next iteration:**
- Service files are well-organized by concern. Most are actively imported by other services or endpoints.
- The lazy import in __init__.py means services load on demand -- don't break this.
- playbook_cache.py provides in-memory caching for rule engines -- critical for performance.

## Iteration 5 — AUDIT-5: 5-Stage Analysis Pipeline Trace
**Task:** Trace every stage, verify all imports, identify broken links.
**Files Changed:** AUDIT_MAP.md (appended), REFACTOR_PRD.md (checked off)
**What I learned:**
- Pipeline is fully wired. All 5 stages execute correctly with graceful degradation.
- Stage 1 (Extraction): StructureExtractor + DefinedTermsResolver + JurisdictionDetector -- all deterministic, no AI cost
- Stage 2 (Classification): RuleEngine.evaluate() -- pattern matching against 75 built-in rules or custom playbook rules
- Between 2-3: ScopeAnalyzer runs scope analysis + jurisdiction overrides
- Stage 3 (Risk Assessment): GeminiAnalyzer.analyze_full_contract() -- the heavy AI call (Gemini Pro)
- Stage 4 (Verification): HallucinationGuard.verify_batch() -- kills AI hallucinations via 4-tier text matching
- Stage 5 (Enrichment): ConfidenceScorer.score_batch() -- 5-factor scoring (0-1) per redline
- Key insight: Stage 3 has a fallback to rule-engine-only mode if AI is unavailable. This means the system degrades gracefully without Gemini API access.

## Iteration 7 — AUDIT-7: Redline Generation Pipeline
**Task:** Map the full redline chain from Generate Fix to Track Changes in Word.
**Files Changed:** AUDIT_MAP.md (appended), REFACTOR_PRD.md (checked off)
**What I learned:**
- Full chain: Generate Fix -> generate_fix() -> FixVerifier -> word diff preview -> Apply -> generateRedlineZDR -> RedlineImplementer.find_anchor() -> generate_track_changes_ooxml() -> insertOoxml()
- find_anchor() uses 3 strategies: hash match (SHA-256) -> exact substring -> fuzzy (rapidfuzz, 80% threshold)
- generate_track_changes_ooxml() uses difflib.SequenceMatcher for word-level diffs -- NOT bulk paragraph replacement
- Missing clause handling: generate_insert_only_ooxml() with InsertLocation.after
- Word Add-in uses insertOoxml() for both violations (replace) and missing clauses (after)
- No broken links. Pipeline is fully wired.
